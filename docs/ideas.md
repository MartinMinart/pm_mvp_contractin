# Бэклог идей и отложенных решений

Этот документ фиксирует идеи, которые сознательно отложены до следующей версии. Мы не удаляем неиспользуемый код и не теряем контекст: каждая идея получает обоснование, текущий статус и план возврата.

## 1. Кривая покрытия вариантов (`renderCoverageChart`)

**Статус:** отложено до следующей версии.

**Где находится:** `site/assets/app.js`, функция `renderCoverageChart`.

**Что задумано:** отдельный график, который показывает, как накопленная доля кейсов растёт при добавлении вариантов процесса. По оси X — номер варианта, по оси Y — накопленное покрытие. График помогает ответить на вопрос: «Сколько вариантов нужно оставить, чтобы покрыть 80–90% кейсов?».

**Почему не включено сейчас:** в `site/index.html` нет узла `#coverage-chart`, поэтому функция не вызывается и график не отображается. При этом покрытие уже выводится текстом в бейдже Pareto на вкладке «Варианты», а данные для построения есть в `site/data/variants.json` (`share_percent`, `frequency`, `top10_coverage_percent`).

**План возврата:**

1. Добавить в `index.html` контейнер `#coverage-chart` в блок вкладки «Варианты».
2. Вызвать `renderCoverageChart` из `renderVariants`.
3. Проверить адаптивность на 1440×900 и в тёмной теме.
4. Добавить подпись «Накопленное покрытие топ-N вариантов».

**Критерий готовности:** график отображается рядом с Pareto, не создаёт вертикального скролла страницы и корректно перерисовывается при смене темы.

## 2. Как добавлять новые идеи

- **Не удалять код сразу.** Если функция или компонент временно не используется, перенести описание сюда с обоснованием.
- **Указывать статус:** «идея», «отложено», «в работе», «отклонено».
- **Фиксировать причину:** почему не делаем сейчас и что должно измениться.
- **Описывать проверку:** как поймём, что идея реализована корректно.
